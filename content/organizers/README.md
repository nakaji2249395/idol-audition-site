# 運営記事と計測

全記事の末尾は同一noteへ接続。価格・有料表記はサイトの案内に表示しない。
既存オーディションサイトのナビから運営記事への導線は作らない。

## 記事の役割

| slug | 検索意図 | 無料で答える内容 | noteで続きを読める内容 |
| --- | --- | --- | --- |
| no-connections | アイドル運営 人脈がない | 知り合いがいない不安と考え方 | 最初に動いた具体的な記録 |
| start-idol-group | アイドルグループ 立ち上げたい / 作り方 | 活動条件を整理する五つの問い | 第1〜3章の企画メモと問い合わせ文 |
| idol-management-beginner | アイドル運営 やってみたい / 未経験 | 引き受けられる仕事と経験の整理 | 第7〜8章の遠回りと進める順番 |
| idol-management-recruitment | アイドル運営 募集 / スタッフ | 求人を見る際の確認事項と立ち上げとの違い | 自分で立ち上げる道を選ぶ人に第1〜11章 |
| recruit-idol-members | アイドルメンバー 募集方法 / 集め方 | 掲載場所・条件・問い合わせ後の準備 | 第3・5・6・9〜11章の実例 |

検索順位・検索数は未測定。費用の実額、収益、具体的な掲載先一覧、求人採用体験は現noteの提供内容にないため、続きを約束しない。
新しい体験の人数・金額・日時は創作しない。2026-10-21にユーザーが明言した無料掲載・問い合わせ・面談・結成・もうすぐ2周年という経験を使う。

## 計測

既存のVercel Web Analytics（Pro）で集計。管理画面の `/admin/journal` に操作案内。
イベントは `journal_article_view` → `journal_note_reached` → `journal_note_click`。`article` プロパティが上表のslug。`version` は計測仕様のバージョン。
記事マウントごとに各イベントを一度だけ送る。表示中タブでnote案内見出しの半分以上が1秒表示されたら到達。クリック時は素早い操作も含めて到達済みとして扱う。
読了や実人数を断定しない。VisitorsはVercelの推計、Totalはイベント回数。再訪・再読み込みは新しい回数になる。note内の購入完了や右クリックメニューでの遷移は計測しない。ブロッカーやJavaScript無効で欠測する。
過去データの遡及不可。テスト操作が本番データに含まれる。

検証：`node scripts/test-journal-tracking.mjs`、ESLint、ビルド、ブラウザで記事別イベントと表示を確認。
